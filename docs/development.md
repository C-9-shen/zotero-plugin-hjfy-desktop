# 开发、测试与发布

## 环境

使用 Node.js 22.8+ 和 npm。`.nvmrc` 固定开发及 CI 使用 Node 22，`package-lock.json` 固定依赖树。源码不依赖本机的绝对路径。

```sh
npm ci
npm run test:unit
npm run typecheck
npm run lint:check
npm run build
```

`npm run build` 先检查源码类型，再将安装包 `zotero-hjfy-desktop-<版本号>.xpi`、`update.json` 和 `update-beta.json` 输出到 `build/`。`build/addon/` 是打包前的插件文件。构建产物不提交到 Git，不再使用 `.scaffold/build/`。

精简后端的翻译纯逻辑模块不依赖 Zotero；归档解包、进度映射和 arXiv 解析位于 `src/utils/`。插件不包含桌面引擎、编译器或 TeX 资源。自动补齐依赖时使用下载的 TinyTeX 自带 Perl 运行官方包管理器；Windows 基础设施更新使用官方更新脚本，关闭命令行 AutoRun，传入固定相对脚本名，不拼接论文内容或路径。

全局最多同时处理两篇论文，同条目运行中或排队时复用任务；队列仅保存在内存中。已有译文绕过队列直接打开分屏，并在排队任务开始时再次检查附件。便携 TeX 首次准备和桌面引擎复制共享初始化过程；精简模式每篇正文保持双并发请求，共享 TeX 缓存的编译阶段串行执行。任务列表关闭后继续执行，插件关闭后等待中的任务不会启动。

附件导入成功后先删除后端记录的临时任务目录，再等待进度笔记写入结束并删除笔记；错误路径保留诊断目录及失败笔记。翻译缓存和运行环境位于任务目录之外，不随成功任务删除。成功任务在列表中只保留状态，不保留逐条日志。

缓存按服务地址、协议、模型、源文本和保护内容计算摘要。先逐段读取旧缓存，再按源码文件合并未缓存段落；每批最多 32 段、约 12000 字符及 48 个语法标记。单段保持完整，最多 16000 字符，可单独超过批次标记预算。

0.3.7 起区分块级文本与行内文本命令：标题、章节和图注独立提取；加粗、强调、脚注等参数递归扫描，命令、选项及花括号分别保护，参数中的文字留在所属段落。列表项、环境、独立公式及文件引用形成边界；行内参数中的空行保留为语法标记，避免递归扫描切断外层段落。未知宏及其参数仍整体保护，不猜测参数用途。批量 JSON 协议和缓存摘要格式保持不变；提取文本或保护内容变化的段落重新翻译，其余旧缓存继续复用。

批量请求和返回使用 `{"segments":[{"id":1,"text":"..."}]}`，ID 是文件内的原始段落序号，语法标记在每段从零编号，无额外边界标记。响应数组可重新排序；未知、重复或非数字段落 ID 拒绝整次响应。0.3.8 起保护标记按桌面端实测规则校验：每个原始标记至少出现一次，不得出现未知标记，按编号替换每次出现的内容；允许换序和重复，不比较出现顺序或次数。段落 ID 仍必须唯一，这与段内保护标记的规则不同。

有效 JSON 中逐段检查非空文本、标记覆盖与未知标记及新增 TeX 语法，合格结果立即使用并写入原有逐段缓存，仅将缺失或无效段落合并重试一次。0.3.10 起，若仍有多个未通过段落，将它们按段落数量分成两组，每组最多尝试两次，不再递归拆分；单段不拆短句，始终沿用原 ID，已成功段落不重复请求。最终仍失败则终止，不静默回退原文。完整标记中的转义方括号、全角方括号、空格及单层反引号可规范化，不推测缺失标记、不重排模型输出。提示词要求保留格式与花括号范围；标记集合校验不证明嵌套格式、引用位置或学术译文准确。旧缓存继续使用同一摘要格式，并按新规则读取。

HTTP 连接失败、超时、408/425/429 和 5xx 每次最多尝试三次，默认等待 1 秒、2 秒；可识别 `Retry-After` 的秒数或日期，单次等待不超过 30 秒。其他 HTTP 错误立即停止该批次，避免对鉴权和地址错误重复请求。等待期间每 250 ms 检查取消。HTTP 重试耗尽后不再进入内容重试或批次拆分；响应截断、协议文本缺失及批量 JSON 错误仍走内容重试。任务统计记录实际 HTTP 请求次数，不记录请求头或原始 HTTP 错误正文。

缓存通过 `IOUtils.writeUTF8` 的独立 `tmpPath` 及 `flush` 写入后原子替换，清理残余临时文件。缓存读取异常仅重译受影响段落，写入异常仍使用本次有效译文；每任务分别提示一次读写异常，避免因缓存故障丢弃有效结果。缓存摘要格式保持兼容。

校验失败时将该次请求文本、模型返回及逐段预期/实际标记、缺失/重复/未知标记写入任务目录 `diagnostics/batch-N-attempt-N.json`；拆分后的尝试沿用父批次递增编号，避免覆盖。不保存 API 配置、密钥或 HTTP 请求头。诊断写入失败不会覆盖原错误。整个任务成功后随临时任务目录清理，任务失败则保留。HTTP 或协议层失败只保留已有的简要错误，不把原始 HTTP 响应写入日志笔记。

0.3.9 起恢复译文时将普通文本中的 `%`、`&`、`#`、`_` 自动转义，兼容模型已返回的对应单字符转义，不重复转义。原始保护内容不参与此转换；缓存仍保存模型文本并沿用原有键，在输出源码时统一恢复。未保护的新命令、花括号、数学定界符等仍拒绝；转义识别不会跨越保护标记拼接，以免掩盖新增反斜杠。

0.3.5 起不再要求结果含中文，已删除名称例外规则。恢复保护标记时，裸控制词后直接跟字母（含中文）会补入分隔空格；该修复同样适用于旧缓存。扫描器整体保护 `looseness` 等已知整数排版参数及其数值；这只改变受影响段落的缓存键，避免复用曾丢失排版参数值的译文。

0.3.11 起，写出精简后端的译文编译副本时，对所有 `.tex` 文件禁用独立一行的固定数值 `\pdfoutput` 设置，避免 Tectonic 的 XDV 模式被误判为 pdfTeX 而加载 `hpdftex.def`。处理保留源码长度、行号及行尾注释，跳过注释、行内 verb、常见代码示例环境及 filecontents；不处理动态赋值或宏定义内嵌写法。日志记录文件及行号。处理发生在提取、翻译和缓存恢复之后，缓存键和原始归档不变。使用实际失败任务的译文副本验证了整篇 XDV 排版，未调用模型或生成 PDF；这不代表已验证全部驱动强制选项和模板。

0.3.12 起，若归档包含与主文件同路径同名、带 `thebibliography` 环境的 `.bbl`，编译副本将 `\bibliography{...}` 改为 `\input{\jobname.bbl}`，同时移除 `\bibliographystyle{...}`，保留附带注释及换行。直接使用归档中的文献条目和引用键，避免缺少 `.bib` 时 BibTeX 覆盖现有 `.bbl`。此处理在所有 `.tex` 文件中执行，跳过注释和示例环境；不修改 `.bbl`、翻译缓存或原始归档。没有传统 `.bbl` 或只有 biblatex `.bbl` 时保持原编译流程。编译结束后读取最终 `.log`，若仍有未定义引用则报错保留诊断，不将其作为成功结果导入。真实译文副本的 XDV 验证覆盖 27 个文献引用键、14 个交叉引用目标及链接标记，不生成 PDF；单元及运行适配测试覆盖引用参数保护、文献表选择、缓存复用及未解析引用的拦截。

## 桌面端实现参考

精简后端参考桌面端 1.0.6.0 的本机模拟 API 验证结果，独立实现段落提取和保护标记恢复，不包含反编译代码、桌面引擎或分析工具。桌面端的 C# 层主要负责配置、队列和命令行适配，LaTeX 翻译由原生 Office 引擎处理。

核查范围包含 C# 核心文件的职责、配置和任务流程，以及提取、请求、校验、缓存和编译相关的原生字符串、局部反编译伪代码与本机模拟 API 探测；未完整恢复原生 Rust 源码，不能据此声称逐行审计了全部引擎。

| 流程       | 桌面端已确认的行为                                                                                             | 精简后端采用方式                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 特殊字符   | 实测自动转义 `%`、`_`、`#`；裸 `&`、新增命令和裸数学定界符会失败并可能回退；完整代码围栏和 JSON 字符串可被剥除 | 普通 `% & # _` 安全转义；批量返回接受完整 JSON 围栏，仍拒绝新增命令和数学语法                      |
| 标记       | 按名称恢复，允许换序与重复，拒绝缺失及未知编号                                                                 | 沿用相同标记覆盖规则，段落 ID 仍严格唯一                                                           |
| 请求       | 默认超时 120 秒、最多三次尝试；实测 401 不重试，429/503 会重试                                                 | 保留 120 秒超时，区分临时错误与配置错误并有限退避                                                  |
| 失败拆分   | 开启拆分后，实测可将失败的多句片段拆开重试                                                                     | 仅缩小完整段落组成的批次，最多一层，保留上下文及请求上限                                           |
| 缓存及任务 | C# 原子写入任务 JSON，SQLite 全局翻译缓存，重试可继承译文 CSV；任务状态可持久化                                | 文本缓存原子替换、异常隔离及有效段落复用；任务队列仍仅在会话内保存                                 |
| 编译       | 原生引擎含多种模板专用处理入口；依赖外部 TeX 工具                                                              | 优先本机 XeLaTeX/latexmk，否则便携 Tectonic；全文 XDV 预检及最终引用校验，保留已验证的模板兼容处理 |

正文尽量按完整段落提取，保留加粗、强调和脚注中的上下文，标题、图注和列表项分别处理。保护标记按名称覆盖校验，允许换序和重复；缺失或未知标记判为无效。桌面引擎在无效结果上可能回退原文，插件桌面适配层会拒绝存在原文回退的结果。

0.3.14 起，`prepareDesktopSource` 在调用引擎前将 SWAM 模板无参数的 `\newcommand{\PaperAuthors}{...}` 改为 `\DeclareRobustCommand`。Office 引擎不翻译这种定义，姓名及机构上标原样保留；标题、摘要和作者说明保持原翻译流程。只修改解压后的 UTF-8 工程副本，跳过注释和代码示例，不放宽正文回退检查。

0.3.15 对照桌面端的本机 TeX 策略：在未指定 Tectonic 路径时，检查 PATH 中的 `latexmk`、`xelatex`、`bibtex` 和 `kpsewhich`；全部存在则使用本机发行版，否则仍使用固定版 Tectonic。显式路径优先。`texCompiler.ts` 集中处理发现、参数与缺依赖报错；本机调用使用 `-norc` 禁止加载项目 rc、`-no-shell-escape` 禁止论文执行外部命令，取消时在 Windows 终止进程树。

原中文小样预检改为加入中文兼容设置的全文 XDV 预检，发生在任何模型请求之前。预检与译文写出复用同一准备过程，包括驱动修正和归档 `.bbl` 保留；最终译文仍独立编译并校验引用。`applyLatexUnits` 在已知拼接边界补齐控制词分隔，修复段外 `\item`、`\par` 与去空白译文粘连，并覆盖相邻保护标记，保持缓存键不变。共享中文设置在独立 figure/table（含星号）之前调用公开的 `\wrapstuffclear`，避免未结束的绕排污染短中文图注。

实际两份失败工程重放复用 198＋183 段缓存、零模型请求，译文分别完成 36 页及 26 页 XDV 排版，最终日志无未解析文献或交叉引用。未额外导出 PDF；XDV 验证未覆盖最终 PDF 转换与 Zotero 导入。

0.3.16 在 `managedTex.ts` 实现缺依赖自动恢复：使用固定版 TinyTeX 官方 Windows 自解压包及 SHA-256，保留完整内核与 expl3 的版本一致性；在插件运行时目录安装 ctex/fandol，用 tlmgr 的精确文件检索定位宏包，再安装其依赖，排除文档与示例目录中的同名副本。仅自动修改独立发行版，不修改本机 TeX。编译及包管理进程串行使用共享编译队列，包管理命令另有串行与合并机制；同一缺失文件只重装一次，每次编译最多修复 96 种依赖，覆盖宏包较多的论文模板。不能修复的源码错误、未知私有文件及重复缺失立即保留诊断。准备过程分解压完成与安装完成两种回执，中断后复用已解压环境；校验失败不执行程序，取消后不发起新的编译或安装。Windows tlmgr 要求自更新时沿用其官方基础设施更新与回滚协议。

独立环境若报告内核与新宏包版本不一致，会同步更新已安装宏包，最多一次。真实工程验证另发现 xeCJK 与 enumitem 的 multiline description 标签分组冲突；中文兼容设置仅在同时加载二者的 XeTeX 工程中，为 multiline 样式启用 enumitem 自身的盒装标签路径，保留多行对齐和标签宽度。归档附带传统 `.bbl` 时同时禁止 latexmk 重新运行 BibTeX，防止缺包重试的强制重编译覆盖文献表。

独立发行版解压后执行 TeX Live 官方 XeTeX 安装后操作，重新生成指向当前目录的 Fontconfig 配置及字体缓存，避免压缩包遗留的构建机路径导致已安装的 FontAwesome 无法加载。完成回执同时记录字体配置状态，旧回执可直接补做此步骤而不覆盖已安装的环境。Babel 缺语言定义的 unknown option 报错按 `.ldf` 文件解析；字体度量加载失败按 `.tfm` 文件定位字体包，同样执行精确查询与安装。

2026-11-17 使用独立下载的 TinyTeX 重放实际失败工程，完成环境校验与解压、tlmgr 自更新、缺包自动安装及字体目录迁移；报错论文的整篇预检完成 40 页排版，两份已有中文译文分别完成 36 页、26 页排版，最终日志均通过引用检查。未调用模型，未生成 PDF；验证范围为 XDV 编译和依赖恢复，不包括最终 PDF 转换或 Zotero 附件导入。

本机发现同时检查 Windows 标准 TeX Live 年份目录和用户 TinyTeX 目录，避免 Zotero 继承旧 PATH 漏检。调用本机或独立编译器时，显式前置所选发行版的程序目录，防止 latexmk 或包管理器调用另一套 kpsewhich/TeX 工具。显式 Tectonic 路径表示首次选择，仍允许缺包自动恢复；独立环境安装成功后，未指定路径的新任务直接复用。

精简后端继续使用带段落 ID 的 JSON 批量协议、逐段缓存和局部重试，未知自定义宏及其参数仍整体保护。回归覆盖段落边界、标记、请求分类与重试上限、段落级缩批、诊断编号及缓存故障；运行适配测试在临时目录检查缓存复用和凭据不进入错误消息，并在 PDF 编译前停止。模拟响应验证不代表真实译文质量或模板编译兼容性。

## 本地开发与 Zotero 集成测试

复制 `.env.example` 为 `.env`，填写本机 Zotero 程序路径和独立的开发资料库路径。不要使用日常资料库。示例配置覆盖脚手架的全局退出命令，避免结束其他 Zotero 会话；开发实例需在必要时自行关闭。

```sh
npm start
```

运行集成测试时，使用独立测试 profile 与 data 目录。以下是 Windows PowerShell 中的本地开发示例，PowerShell 仅用于开发命令，插件运行不依赖它：

```powershell
$env:ZOTERO_PLUGIN_ZOTERO_BIN_PATH = 'C:/Program Files/Zotero/zotero.exe'
$env:ZOTERO_PLUGIN_PROFILE_PATH = Join-Path (Get-Location) '.scaffold/test/profile'
$env:ZOTERO_PLUGIN_DATA_DIR = Join-Path (Get-Location) '.scaffold/test/data'
$env:ZOTERO_PLUGIN_KILL_COMMAND = 'echo Isolated test process stopped'
$env:MOZ_NO_REMOTE = '1'
$env:MOZ_HEADLESS = '1'
npm test -- --exit-on-finish
```

桌面运行环境自检需要本机安装兼容的幻觉翻译桌面端。其他可选测试按夹具环境变量启用，未提供时跳过相应测试。

| 环境变量                                | 用途                                                     |
| --------------------------------------- | -------------------------------------------------------- |
| `HJFY_TEST_PDF`                         | 现有 PDF 路径；验证分屏、主从滚动、缩放及已有日志不变    |
| `HJFY_TEST_ARCHIVE` + `HJFY_TEST_CACHE` | 指定论文源码归档与完整译文 CSV；验证桌面端缓存编译及导入 |
| `HJFY_TEST_DOWNLOAD=1`                  | 启用 arXiv 源码真实下载检查                              |
| `HJFY_TEST_TECTONIC_ARCHIVE`            | 固定版本官方 Tectonic ZIP；轻量后端下载校验的本地夹具    |
| `HJFY_TEST_TEX_CACHE`                   | 已准备的 Tectonic 资源缓存目录                           |
| `HJFY_TEST_LITE_BASE_URL`               | 本机模拟 API 地址，例如 `http://127.0.0.1:19086/v1`      |

桌面缓存编译测试复用此前译文，并将模型地址临时改为不可用的本机端口，防止缓存缺失时发起付费请求。它仍需本机已有桌面模型配置与 TeX 环境，不是可在任意机器上执行的纯逻辑测试。

### 轻量后端夹具

先在另一个终端启动：

```sh
node test/fixtures/mock-latex-api.mjs
```

模拟服务只监听本机，返回固定测试中文，不访问远程模型。设置上述三个轻量后端环境变量后运行 Zotero 测试，可验证原生 HTTP、密码管理器、便携 TeX、附件和日志链路。测试服务使用公开的固定测试密钥；不要将真实 API 密钥填入夹具。

便携编译器固定为官方 Tectonic `0.17.0` Windows x64 MSVC ZIP，SHA-256 为 `f61ce51f0b0ade1015b7de7ef368541c5424e9756ecbd0d7af97d6d48030845f`。版本、下载地址和校验逻辑集中在 `src/modules/latex/portableTex.ts`；升级时同步更新摘要及测试夹具。编译使用 `--untrusted`，不为论文开启 shell escape。

`src/modules/latex/chineseCompilation.ts` 为两种后端提供中文编译兼容设置：在主文件的文档类之前向 `fontspec` 传递 `no-math`，在正文前关闭 XeTeX 的 microtype 字体微调；模板同时加载 `soul` 与 `xeCJK` 时，使用 `xeCJKfntef` 提供保留原色的中文断行高亮。精简模式在翻译完成后处理编译副本，桌面模式在交给外部引擎前处理解压出的入口文件；不处理正文片段、注释或代码示例中的伪入口。桌面模式保留非 UTF-8 文件的原始字节，由外部引擎处理。

预先准备资源缓存可以避免回归测试重复下载宏包。测试需同时提供 ZIP、缓存和本机 API 地址。

## GitHub 检查与发布

普通推送及 PR 执行 `.github/workflows/ci.yml`：使用 Node 22、`npm ci`、格式检查、Node 逻辑测试、源码及测试类型检查、生产构建，并上传 XPI 和更新清单作为 Actions 产物。回归覆盖队列并发和去重、失败隔离、已有译文绕过忙碌队列、日志清理、批量请求和缓存复用、命令边界和整数参数保护；Zotero 集成测试另验证实际任务窗口和笔记删除。CI 不启动 Zotero，也不调用模型 API。

正式发布使用 `.github/workflows/release.yml`。准备步骤如下：

1. 确认 `package.json` 的版本，使用 npm 同步更新 `package-lock.json`，并完成本地检查及必要的 Zotero 回归。
2. 提交源码和文档；不提交 `.env`、API 凭据、测试资料库、下载的引擎、论文及构建产物。
3. 准备与版本一致的 `版本号` Git 标签（例如 `0.3.16`），之后推送分支及该标签。
4. 标签工作流核对版本并重新检查、构建，随后由脚手架创建 GitHub Release、上传 XPI，并维护 `release` 标签下的更新清单。

Release 仅需要仓库提供的 `GITHUB_TOKEN` 及 `contents: write` 权限，不需要在源码中保存个人令牌。普通分支推送只运行 CI，不会发布安装包。`npm run release` 在本地可能修改版本、提交、打标签并推送，不能当作普通验证命令运行。
