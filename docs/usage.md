# 使用说明

在 Zotero 中将 arXiv 和部分 alphaXiv 论文翻译为中文 PDF，自动添加到原文献附件，并在同一标签页分屏阅读原文与译文。

插件默认调用本机**幻觉翻译桌面端**，也可选择实验性的**精简实现＋便携 TeX**。两种方式均可从 arXiv 获取 LaTeX 源码。没有 arXiv ID 的 alphaXiv 条目使用单独设置的 PDF 后端，默认仍为桌面端。

## 功能

- 从 DOI、URL、存档 ID 或 Extra 识别 arXiv ID，保留指定版本。
- 批量排队翻译，最多同时处理两篇，运行期间可继续加入任务；单篇失败不影响其余条目。
- 在任务列表和文献的日志子笔记中显示进度，无常驻翻译通知；成功后自动清理日志，失败时保留。
- 已有同版本译文时直接打开分屏，不重复翻译、导入或新建日志。
- 原文在左、译文在右，默认由译文控制跟随翻页和滚动，可切换主窗口并手动校准位置。

## 环境与翻译方式

面向 **Windows x64**。插件声明兼容 Zotero 7–10，实际运行验证使用 Zotero 10.0.8；其他版本尚未逐一验证。

| 翻译方式               | 模型配置               | 编译环境                        | 状态                   |
| ---------------------- | ---------------------- | ------------------------------- | ---------------------- |
| 幻觉翻译桌面端（默认） | 复用桌面端已启用的模型 | 需自行安装 TeX 及论文所需宏包   | 已完成真实论文翻译验证 |
| 精简实现＋便携 TeX     | 在插件中独立配置 API   | 自动下载 TeX 环境并补齐缺失宏包 | 实验性，支持范围有限   |

两种方式的插件运行均不需要 PowerShell、CMD、Node.js 或 Python。桌面端模式仍需要安装幻觉翻译桌面端，但不必保持其窗口打开。模型 API 可能收费。

**alphaXiv PDF 翻译要求文献 URL 为 alphaXiv 的 `/abs/…` 论文页，并且条目下已有下载到本机的原文 PDF。** 桌面 PDF 后端首次使用会从桌面端安装目录复制约 364 MiB 的运行资源。独立 PDF 后端使用单独安装的 BabelDOC，不需要幻觉翻译桌面端或 TeX。

### 独立 PDF 后端（BabelDOC）

在 PowerShell 中创建专用 Python 环境并安装已验证版本：

```powershell
py -3.12 -m venv "$env:USERPROFILE\.venvs\hjfy-pdf"
& "$env:USERPROFILE\.venvs\hjfy-pdf\Scripts\python.exe" -m pip install BabelDOC==0.7.1
```

在「设置 → 幻觉翻译」中选择「独立 PDF 后端（BabelDOC）」，填写虚拟环境内 `python.exe` 的绝对路径，并设置下方的 API 地址、模型名和密钥。独立 PDF 后端仅支持 Chat Completions，适用于带文本层的 PDF；不保证扫描件、复杂表格和图内文字的翻译。首次运行可能下载排版模型和字体。失败诊断保留在 Zotero 配置目录的 `hjfy-pdf/tasks` 下。

## 安装与配置

1. 从本仓库 [Releases](https://github.com/C-9-shen/zotero-plugin-hjfy-desktop/releases) 下载 `.xpi`。若尚无发行包，可按[开发说明](development.md)自行构建。
2. 在 Zotero 中打开“工具 → 插件”，从右上角菜单选择“从文件安装插件”，选择 `.xpi`。
3. 进入“设置 → 幻觉翻译”，选择“翻译方式”。默认使用幻觉翻译桌面端，选择自动保存，从下一次翻译生效，无需重启。

### 幻觉翻译桌面端（默认）

1. 安装幻觉翻译桌面端，并在其中配置、启用可用的模型。
2. 安装 TeX 环境，确保 `xelatex`、`pdflatex`、`bibtex`、`kpsewhich` 可从 PATH 调用，并准备论文需要的宏包。
3. 插件通常能自动识别商店安装及数据目录，相关设置留空即可。也可手动填写路径，或按配置名称选择模型。

桌面引擎接入已在商店包 1.0.6.0 上验证。其他桌面端版本的引擎接口或配置格式可能存在差异。

### 精简实现＋便携 TeX（实验性）

1. 将翻译方式切换为“精简实现＋便携 TeX（实验性）”。
2. 填写 API 基础地址、模型名称及协议。地址应包含服务要求的 API 前缀（常见为 `/v1`），插件会追加 `/chat/completions` 或 `/responses`。
3. 点击“设置或删除 API 密钥”。无需鉴权的本机服务可以留空。
4. Tectonic 路径通常留空。优先使用完整的本机 TeX 工具（`latexmk`、`xelatex`、`bibtex`、`kpsewhich`），并检查 Windows 标准 TeX Live 安装目录，避免 Zotero 继承的旧 PATH 漏检。采用 XeLaTeX 编译并由 latexmk 自动处理文献与重编译；没有这些工具时复用已配置的独立 TinyTeX 环境，或首次下载并校验固定版 Tectonic。填写 `tectonic.exe` 路径会先使用该程序；缺包时仍会自动恢复。
5. 0.3.16 起，编译发现缺包或内核过旧时，自动下载固定版 TinyTeX（Windows x64，初始下载约 70 MiB，中文字体及后续宏包另需下载），通过 SHA-256 校验后解压到插件缓存目录。自动安装中文排版基础包，再从 TeX Live 仓库查找缺失文件所属宏包，连同依赖下载安装并重新编译。包管理器要求更新时也自动处理。网络中断后可重试；解压完成的环境与已安装宏包会保留复用。

翻译前会用加入中文支持的整篇源码进行 XDV 编译预检，先尝试自动补齐依赖；仍无法编译时保留报错，尚不请求模型。预检输出保存在失败任务的 `preflight-output/`。译文仍需单独编译和检查引用。预检不保证译文长度变化后所有模板都能正常排版。

精简实现翻译正文、标题、章节和图注等已知文本，保留公式、引用、作者、代码、宏、表格内容及参考文献。仅支持 UTF-8 源码；复杂宏、动态文件引用、超长段落或依赖外部工具的模板可能无法处理。

0.3.7 起按完整段落保留加粗、强调和脚注中的文字上下文，标题、图注、列表项分别提取。行内命令、选项和花括号仍使用标记保护；未知自定义宏及其参数保持原样。提取方式变化的段落会重新翻译，其余有效缓存继续复用，无需清空缓存。

请求模型前先复用逐段缓存，再将同一文件内剩余文本合并为批次，每批最多 32 段、约 12000 字符及 48 个语法标记，同时请求最多两个批次。单段保持完整，标记较多时单独请求。模型通过带段落 ID 的 JSON 返回译文，公式与命令使用段落内标记保护，再按 ID 放回原位置。有效段落立即缓存，仅重试未通过的段落。0.3.8 起按桌面端方式通过编号恢复保护内容，允许标记随中文语序换序及重复；缺失或未知标记仍报错。不再检查译文是否含中文；空内容、段落缺失和新增 TeX 语法仍会报错。

0.3.10 起参考桌面端补强失败处理：临时连接错误、超时、限流和服务端错误最多尝试三次，等待后重试；鉴权及地址错误直接报错。内容校验重试后仍有多个失败段落时，将它们缩成两组再尝试一次处理流程，单段始终完整，不拆成短句。已成功的段落继续复用；缓存读写故障会提示，但不会丢弃本次有效译文。最终仍失败时明确报错，不静默保留原文。

## 翻译与阅读

1. 选择一个或多个 arXiv 或 alphaXiv 文献，右键选择“幻觉翻译 arXiv: 翻译当前文章”。选择文献条目，而非其 PDF 附件。
2. 有条目需要排队翻译时自动打开任务列表，显示“排队中”“运行中”“已完成”或“失败”。也可从“设置 → 幻觉翻译 → 打开翻译任务列表…”重新打开。最多同时处理两篇，其余按加入顺序等待；重复提交同一条目会复用当前任务。
3. 展开文献，打开“幻觉翻译日志 · 进行中”子笔记查看详细日志。成功导入中文 PDF 后，该次日志笔记和临时诊断目录自动删除；失败原因和诊断目录保留在笔记内。
4. 对已完成翻译的文献再次执行该菜单，直接进入单标签页分屏，无需等待翻译队列。若本地没有原文 PDF，则仅打开译文。

关闭任务列表窗口不会取消任务，点击“清除已完成记录”可移除列表中的成功记录。任务列表和等待队列仅保存在当前 Zotero 会话内，重启后不会自动恢复。精简模式可同时翻译两篇的正文，编译阶段依次执行，以避免同时写入共享 TeX 缓存。

默认右侧译文为主窗口，蓝色边框和滚动条标识主窗口。在任一侧 PDF 正文中右键，选择“设为主窗口（另一侧跟随翻页）”可切换控制方向。从窗口可以单独移动以校准两侧排版差异，后续跟随保留相对页进度；主窗口工具栏缩放会同步到另一侧。

## 常见问题

**翻译失败或未生成 PDF**：先查看文献下的日志子笔记。桌面端模式检查已启用模型和 TeX 环境；精简模式检查 API 配置及首次下载的网络连接。两种模式都可能因论文模板或宏包需求而编译失败，诊断文件可用于排查。

**提示缺少 `wrapstuff.sty`**：便携 TeX 的旧宏包集合不包含该包，单独复制新版文件还可能遇到 LaTeX3 版本不兼容。0.3.16 起精简模式自动准备兼容的 TinyTeX 环境并下载该包及依赖；已有完整本机 TeX 时优先使用。首次自动补齐需联网，翻译前完成依赖预检。若仓库中没有对应文件，会明确报出缺失文件，可能需要论文作者补全归档。新版同时在独立图表浮动体之前结束尚未完成的绕排，避免中文段落缩短后，绕排状态进入图注引发 `Not in vertical mode`；图表内容与标签保留。

**提示“部分文本翻译失败并回退为原文”**：插件会拒绝导入存在原文回退的结果。若使用 SWAM 模板，0.3.14 起桌面端模式会将无参数的 `\newcommand{\PaperAuthors}{...}` 改为等效的稳健作者宏，保留姓名和机构上标，避免作者名单被当作正文翻译而导致整篇拒绝导入。正文翻译失败仍报错。安装新版、重启 Zotero 后重试即可，已有有效缓存无需清空。

**编译提示 fontspec 选项冲突、XeTeXglyph 字体错误或 soul Reconstruction failed**：0.3.13 起两种模式都在编译工程中预先传递 `fontspec` 的 `no-math` 选项，并在 XeTeX 下关闭 microtype 的字体微调，避免旧版 XCharter 和 Type 1 字体冲突。加载 `soul` 和 `xeCJK` 的模板使用支持中文断行的高亮实现，保留高亮颜色。安装新版、重启 Zotero 后重试，已有翻译缓存可继续使用。

**桌面端翻译是否支持并发或合并请求**：当前插件传给引擎的 `--concurrency` 为 `2`，表示最多同时发起两个翻译请求。引擎逐段报告进度不等于完全串行。这版 Office 引擎没有暴露把多个 LaTeX 段落合并为一次请求的参数；其批处理目录参数用于处理多份文档。精简后端采用多段合并请求，具体批次限制见上文。

**切换方式后仍打开旧译文**：插件优先复用已有同版本译文。切换方式只影响新的翻译任务，已有附件不会自动替换。

**是否能完全离线**：远程模型调用、源码获取、便携 TeX 首次下载和缺失资源下载均需联网。宏包及成功翻译的片段会缓存，但不能保证任意论文离线处理。

**保护标记校验失败**：0.3.8 改用桌面端的标记覆盖与名称校验，不再因“标记顺序变化”或重复标记拒绝译文。所有原标记至少保留一次；缺失或出现未知编号会先重试，0.3.10 起还可对仍失败的多个段落缩批重试。段落 ID 仍需唯一，禁止跨段混用标记。仍失败时保留诊断目录中的 `diagnostics/*.json`，其中包含请求文本、模型返回及标记差异。保持 API 地址、协议和模型一致可复用已成功的段落缓存，无需清空缓存。

**模型引入未转义的 TeX 语法**：0.3.9 起自动转义译文普通文本中的 `%`、`&`、`#`、`_`，例如将“各占 50%”写为可编译的 `50\%`；已转义的符号不会重复转义，受保护的原始命令和公式保持原样。新增命令、公式定界符或花括号等仍会触发校验和重试。安装新版并重启后重试，无需清空缓存。

**模型未返回中文译文**：0.3.5 起已取消这项检查，`Robomimic`、`RoboEval` 等名称可以原样返回。安装新版并重启 Zotero 后重试；无需删除已有缓存。

**编译提示 Undefined control sequence 或 Missing number**：0.3.5 修复了段内保护宏与中文粘连的问题，并将 `\looseness=-1` 等整数排版参数整体保护。0.3.15 进一步覆盖段落外的 `\item`、`\par` 及相邻保护标记边界，避免模型去掉空白后出现 `\item我们提出`。恢复时自动补上必要分隔，旧版有效缓存仍可使用，无需重新翻译全文。若仍失败，请提供诊断目录中的编译日志。

**编译在 hpdftex.def 中报告 Hy@pdfmajorversion 未定义**：部分 arXiv 源码含有独立一行的 `\pdfoutput=1`，导致便携 TeX 错选 pdfTeX 驱动。0.3.11 起在译文编译副本中禁用这类固定数值设置，并在日志标明文件和行号；注释、代码示例及其他源码保留。已有有效翻译缓存可继续使用，无需重新翻译全文。

**主文件无法唯一确定**：在精简模式设置中填写 LaTeX 主文件相对路径，例如 `main.tex` 或 `paper/main.tex`。仅支持花括号形式的 `\input{...}` 和 `\include{...}` 引用。

**引用变成 `(?)`、`[?]` 且无法跳转**：部分 arXiv 源码只包含已生成的 `.bbl` 文献表，没有原始 `.bib` 数据库。0.3.12 起精简后端优先使用与主文件同名的传统 BibTeX 文献表，避免重新运行 BibTeX 将它覆盖为空表，并保留原引用键和文献条目。没有此类文献表时仍使用原编译流程；biblatex 格式的 `.bbl` 不作直接替换。编译完成后检查未解析的文献引用和交叉引用，发现问题时保留诊断而不导入含问号的译文。安装新版后，若条目下已有错误译文，请先移除旧译文 PDF 附件，保留原文及文献条目，再点击翻译；否则会按原有规则直接打开已有译文。已有翻译缓存无需删除。

## 数据与凭据

论文文本会发送到所选模型服务。桌面端模式读取当前 Windows 用户的桌面端配置和凭据；精简模式的 API 密钥保存在 Zotero 密码管理器中。插件不将密钥写入任务笔记或命令行。

任务文件和缓存保存在 Zotero 配置目录：桌面端模式使用 `hjfy-desktop/`，精简模式使用 `hjfy-lightweight/`。成功导入附件后删除该次任务的源码、编译日志和临时输出；失败任务的诊断目录保留。翻译片段缓存、引擎和便携 TeX 资源继续保留，供重试或后续任务复用。分享异常日志前请检查其中的论文内容及本地路径。
